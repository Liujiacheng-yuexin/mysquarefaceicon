# 游戏页面独特内容与事实 QA 标准

版本：1.0 · 2026-09-03 · CONTENT-QA-001。成果验收状态只以权威 HTML 看板为准。

本标准将现有规则落到游戏内容的逐项核验，不另创 SEO 评分、发布许可或任务状态表。配套 [单页审核记录模板](game-page-review-template.md) 只存事实与证据；通用规则仍见 [RULES.md](../../RULES.md)，项目决策见 [SEO_RULES.md](../../SEO_RULES.md)，结果分级见 [QUALITY_STANDARD.md](../../QUALITY_STANDARD.md)。

## 1. 使用范围与不可变边界

- 用于后续经用户授权的游戏记录、游戏说明、External Tool 内容和 AI 草稿审核。先完成一个页面的事实核验与用户验收，再考虑下一页或批量工作。
- `/` 继续承担 Square 主意图；Oval 保持独立圆脸意图；Pixel 是外部工具说明与出站页。不得因内容审核自动改变 URL、canonical、index/noindex、sitemap、H1、首屏或模块顺序。
- 本项只建立标准和可复制记录，不改现有页面、GameRecord、Schema、播放器或自动发布逻辑，不追溯撤销 29 条既有用户验收。
- LICENSE-GATE 材料补充任务已取消；不重新建立该待办、不催交材料、不读取归档作为新的工作指令。现有 Registry 的 UNKNOWN 事实与权限校验保留，取消不等于许可核验通过。本标准不是另一份 Square/Oval 补材料清单。
- 不复制竞争站游戏、图片、评论或文案，不反编译或修改 Square/Oval SWF。不能以凑完整字段、修复编译、补关键词或满足字数为理由编造内容。

适用规则：IA-02/03、CT-01～07、KW-05～07/10～16、TR-06/07/10、META-06/09、AY-03/06、PS-03～08。

## 2. 先证明独立价值，再组织内容

审核人须回答：谁来此页、要完成什么操作、为何现有页面不能同样解决、该页至少一项独有贡献在哪里。

- 接受的独有贡献沿用 CT-05：原创数据、实测结果、完整步骤、可复用模板、工具输出或独特解释；写出具体段落和证据，不只勾选类别。
- 将候选页与最接近的站内页面并排审阅，去掉游戏名、颜色和形状词后，仍应有与该游戏有关的操作差异、限制、结果解释或选择依据。仅替换名称、词序、同义词或插图，不能证明独立价值。
- 共用的 Ruffle 加载说明、导航、页脚和通用安全提示可以复用，但不计作该页独有内容；不同模板或更多段落也不自动增加独有价值。
- 不设 800 字硬门槛。CT-08 与 RULES 附录 B 的页面类型词数仍是“应该”级检查，不是必须补足的排名目标；不足须解释，不能用注水补齐。Google 明确没有偏好的固定字数，并强调实际价值与经验。[一手依据](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)
- 相似度工具只能提示人工复核；本项不新增任意百分比阈值、不发明 qualityScore 算法。需要质量分时只用 RULES 附录 A；输入不全保留 null/未验证，不用 0 假装已测。
- 没有独立价值的新草稿不进入发布候选。现有页面若需合并、删除或改索引，必须另行分析 GSC/外链、提出方案并取得确认，不在此审核中自动处理。

Google 的规模化内容滥用政策针对以操纵搜索为主要目的、缺乏用户价值的大量内容，不论由人还是自动化生成。不能把“AI 写成”当成一律失败，也不能把“人工写成”当成一律通过。[一手依据](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content)

## 3. 每条事实的证据规则

记录单位是“具体主张”，不是整个页面的一枚通过标记。每项至少写：claim ID、GameRecord 字段/可见位置、原句、适用环境、证据路径或来源 URL、原验证日期、结果、未覆盖范围和复核人。个人反馈只保留必要的匿名问题，不把邮箱、账号或身份写入公开证据。

| 事实状态 | 使用条件 | 对外表达边界 |
|---|---|---|
| 已核验（限定范围） | 在注明的版本、环境和日期实际观察到；证据可复查 | 只陈述实测范围，不外推到全部浏览器、设备或内部操作 |
| 来源有记载／本站未实测 | 可访问的一手文档明确记载，已记录原文位置和日期 | 明确归因于来源；不能写成本站已经测试 |
| 未验证／UNKNOWN | 没有证据、证据过期、无法访问或尚未运行 | 保留未知或限制说明；不发布肯定功能或权利承诺 |
| 不通过 | 有失败、矛盾、错误来源或不符实际的主张 | 标明失败；在授权范围内修订并重新核验，不以总分抵消 |
| 不适用 | 本页类型确实没有该功能，且有理由 | 例如外链页没有本站全屏；不是把没测的功能改成不适用 |

这些是审核记录中的事实标签，不是新增 GameRecord 枚举。总体仍用 QUALITY_STANDARD 的“通过／有条件通过／不通过／未验证”；未知不是通过，有 P0 不能写“有条件发布通过”。

证据的能力不能混用：

- 源码和结构检查证明字段、链接、声明或绑定存在；不证明玩家能完成操作。
- 原始 HTML/SSR 与水合页面证明可见内容、schema 和渲染一致；不证明来源、版权、真实使用效果。
- 浏览器操作只覆盖实际测过的步骤；模拟窄屏不等于真机。首屏没有横向溢出，也不能证明说明没有被截断。
- 官方说明可以支持有归因的描述，不能代替本站实测；旧检查只支持原日期与版本。HTTP 200、能嵌入或仓库文件存在不能证明许可。
- `PUBLISHED`、`PROJECT_ASSET`、非空数组和自动测试 exit 0 都不是独有内容或人类事实审核的认证。

## 4. GameRecord 字段到核验动作

字段以当前 [game-schema.ts](../../lib/games/game-schema.ts) 为准；不把审核表里的 evidence/reviewer 等字段直接塞进现有记录。

| 字段/内容 | 必须核验的动作与最低证据 | 不得推断 |
|---|---|---|
| `seo.searchIntent`、`content.summary`、`content.description` | 记录独立意图、最近似站内页、独有贡献及可见位置；核对首段能直接说明用途 | 名称不同即意图不同；现有排名已经证明价值 |
| `controls[].label/description/inputMethods` | 逐个控制记录入口、准确按钮名、输入方式和观察结果；分别测页面外围控件与游戏内部控件 | 页面 Play 的 Enter 测试通过就代表 SWF 内部可键盘操作；按窄屏点击即触控通过 |
| `howToPlay[].title/text` | 从未启动状态按文案逐步执行，写下前置条件、准确操作、可见结果和限制；导出须验证实际得到的结果 | 看到 save 文案即保存成功；未确认导出格式/尺寸却宣称 PNG、透明背景或任意分辨率 |
| `features[].title/text` | 每个能力句对应一次实测或有归因的一手说明；样式判断标为编辑解释 | “免费使用”意味着商业许可；经典、original、官方等词自动证明来源权利 |
| `tips[]` | 写明所解决的问题、适用条件、依据和预期帮助；通用建议与实测结论分开 | Reload 必定修复；横屏保证可用；VPN/代理能绕过站点或组织限制 |
| `mobile.support/orientation/verifiedAt/note` | 分开记录本站页面与实际生成器；列设备/浏览器、模拟或真机、宽高/方向、启动/内部控制/结果保存的各自状态 | 页面响应式通过即游戏移动端全面支持；复制桌面日期填 verifiedAt |
| `fullscreen.availability/mode/note` | 真的进入和退出全屏；记录浏览器限制及失败；仅按钮存在属于源码证据 | 有 API 或图标即全屏已验证；外部工具拥有本站全屏能力 |
| `player` 与加载/错误文案 | 实测 idle/loading/ready 或真实错误/重试；网络记录区分点击前后；失败场景注明真实或 fixture | 任意资源计数代表 CWV；正常启动通过即所有错误恢复通过 |
| `source`、`license.registryRecordId`、`license` | 与现有 [License Registry](../../data/game-license-registry.json) 逐项对应；公开文案、来源 URL 和允许的交付方式一致 | 哈希一致即来源/权利核验；UNKNOWN 当 Allowed；直接链接许可扩大为 iframe、镜像、再分发或商业许可 |
| `images[]` | 核对角色、实际图片、alt、真实尺寸、出处和与游戏的关系；示意图明确标注 | 项目本地图片天然原创/授权；curated 示例就是实际游戏输出或用户投稿 |
| `faq[].question/answer` | 每问附真实问题依据、答案证据和可见位置，执行下节专门审核 | FAQ 数量越多越好；编造用户频次或热门问题 |
| `seo.schemaTypes` 与实际 JSON-LD | 比对数据、构建/原始 HTML、浏览器水合结果及用户可见内容 | schema 语法通过就代表事实正确或必获富结果 |
| `relatedGameIds`、`route`、`seo` | 记录真实相关理由、入链来源和实际目标；检查 External 标签、canonical/index/sitemap 与冻结边界 | 把指南当游戏；手填虚假入链数；审核通过后自动 index |
| `author`、`publication`、`measurements` | 署名、日期、分数和统计各自对应实际来源；未核实保留 null/UNKNOWN | Agent 冒充真人编辑；部署日替代内容更新日；把未知统计写成 0 |

注意当前结构要求 `controls/howToPlay/features/tips/faq` 为非空数组。它没有逐条事实证据字段，也不自动判断语义真实性。无真实 FAQ 时不得虚构问题过构建；该候选记录先不进入发布流程。是否改变可选字段/渲染规则属于另一个经确认的代码任务，本项不放宽检查。

## 5. FAQ 必须回答真实问题

合格的问题依据包括：实际操作中观察到的障碍、一手使用说明中的限制、真实但已匿名化的反馈或可复核查询。编辑也可根据真实流程主动拟问，但须标注“编辑拟问”，不能冒充已有用户反馈、热门搜索或统计频次。

逐问核对：

1. 这个问题是否与当前页面和用户操作有关，而非为了再塞一次关键词？
2. 答案的每个功能、保存、平台兼容、来源和权利主张是否都有匹配证据？未知部分是否直接说明？
3. 是否与 How-to、提示、按钮、条款/来源说明矛盾，或只是重复另一个 FAQ？
4. 用户能否在页面看到完整答案？折叠允许，但内容须在 DOM 中，能用键盘展开，窄屏不可被裁切。
5. FAQ schema 是否只包含实际显示的问题与相同答案？不为 External Tool 输出本站可玩、本站拥有的 VideoGame/WebApplication 声明；保留现有 WebPage + 合适 FAQ/Breadcrumb 的边界。

不要承诺 FAQ 富结果或排名收益；结构化数据必须描述可见内容，正确标记也不保证搜索展示。[一手依据](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)

## 6. 当前三条记录的校准示例

以下仅用当前源码与有日期的历史 QA 说明证据边界，不是新一轮完整内容/功能认证，也不是授权修改现有文案。

| 记录 | 可复核依据与独立方向 | 仍须保留的边界 |
|---|---|---|
| [Square](../../data/games/square-face.ts) · `/` | 方脸创建；首页内容/播放器绑定见 [MIG-SQUARE 原 QA](../quality/evidence/mig-square-001/checks.json)；说明须针对真实方脸流程 | 已验收的是本地绑定；外围启动/重载证据不覆盖所有内部控制、真实全屏或保存。`mobile.verifiedAt`、作者、质量分仍为 null，许可 UNKNOWN |
| [Oval](../../data/games/oval-face.ts) · `/oval-face-icon-generator` | 圆脸创建；[MIG-OVAL 原 QA](../quality/evidence/mig-oval-001/checks.json) 保留独立页面和本地绑定检查 | 完整模板迁移未完成；历史窄屏入口偏低仍存在，不用响应式通过冒充首屏达标。内部控制/导出/真机不能沿用 Square 结论，许可 UNKNOWN |
| [Pixel](../../data/games/pixel-art-avatar.ts) · `/pixel-art-avatar-icon-generator` | 外部像素头像工具说明；[MIG-PIXEL 原 QA](../quality/evidence/mig-pixel-001/checks.json) 覆盖本站出站入口、类型标签和 FAQ/schema 一致性 | `DIRECT_LINK_ONLY`；本站新标签导航通过不等于外站编辑、保存或手机可用。当前移动能力 UNKNOWN，不扩大来源条款含义，不把项目示意图当外站输出 |

这三条记录的 `seo.semanticCoverage.score/reviewedAt` 均为 null；topics 是现有主题列表，不是已完成 SERP 前十分析。`measurements.qualityScore`、`inboundLinkCount` 和真实发布/更新日期未核实，不能通过填写表格就变成已测。

反例与处理：

- “换个游戏名即可发布 50 页” → CT-02/05 不通过，先证明独有价值。
- “按钮和类型都存在，所以已验证导出与触控” → 证据不充分，拆分为源码存在与行为未验证。
- “Pixel 可在本站直接编辑/全屏，所有手机均可用” → 与 External/未知移动边界冲突，不发布此主张。
- “所有头像可任意商用／本站已获授权” → 不能从可玩或已有验收推出权利，保留现有未知事实；不因此恢复取消的补材料任务。
- “FAQ 是 AI 写的，已通过字段检查” → 只证明结构；未有人类内容复核，不得称 CT-06 通过。

## 7. AI 草稿到用户验收的执行顺序

1. 从当前看板单项及已确认范围开始；记录原文件/URL、冻结边界、相关源码和证据版本。
2. 先填审核模板中的事实表、未知项与独立价值，再写草稿。AI 只能基于这些输入组织表达；不自行补作者、许可、设备兼容、统计或日期。
3. 对每条新主张回查证据；编辑检查准确性、语气、重复和可读性。人类尚未复核时，`humanReview` 明确为未完成，Agent 自查不冒充人类签字。
4. 批量前先完成一个样例并取得用户验收；内容未知的新草稿不进入公开目录、推荐或 sitemap。此为人工流程要求，当前没有新增自动拦截器。
5. 实际页面获准修改后，执行对应测试、原始 HTML/水合比对及移动/桌面检查。SEO 的 KW-01/02、KW-04、canonical/index/内链分别记录，不以 `seo:check` 的 0 must 冒充人工语义覆盖通过。
6. 保留失败日志，修订后单独记录复测。更改字段、外站行为、证据版本或来源失效时，重查受影响主张；不修改旧验证日期伪造新测试。
7. 把事实记录/检查证据链接回同一 HTML 看板，只设 `待验收`。由用户明确验收后才更新完成；部署和下一任务各自仍需相应指令。

审核记录是证据附件，不另设全项目状态表。CONTENT_PLAN 是技能必读入口；website-quality-supervisor 按该入口读取本标准，再把实际结果写回看板。

## 8. 检查、评分与发布必须分开

| 检查层 | 使用的现有入口/动作 | 能说明什么；不能说明什么 |
|---|---|---|
| 数据结构与权限一致性 | `npm run games:check`、`npm run metadata:check` | 校验记录与索引/metadata 契约；不替代事实与独有价值审核 |
| 相关已验收实现回归 | 按范围选择 `square-home:check`、`oval-page:check`、`pixel-page:check`、`game-template:check` 等 | 校验相关代码/渲染契约；只运行适用项，不把未运行写通过 |
| 可见内容与体验 | 原始 HTML + 水合；桌面与 390/360px；相关键盘、控件、文本全文、真实/模拟设备边界 | 记录具体 URL/步骤/截图/日期；不从截图数量推导全部功能质量 |
| 本地 SEO | 已启动的 production build；单一正确 base 执行 `seo-check`；人工 KW-04 | 自动位置/索引/链接检查与人工 SERP 语义检查分列；不自动插词 |
| 工程与平台 | 页面实现相关 type/lint/tests、Next build；发布相关 Cloudflare build | 发布必需项缺失/失败不能跳过；纯标准文档变更可说明未触及运行代码并仅做文档/看板验证 |
| 用户验收与生产 | 用户验收；另获部署指令后完整发布门禁与 `seo:prod` | 局部 QA、用户验收、生产上线是三件事；任一 P0 未关闭，发布不通过 |

项目 KW-04 的覆盖门槛、KW-02 最低出现、附录 A 评分及附录 B 词数来自项目 RULES，不宣称是 Google 排名公式。本项未完成三页的 KW-04、新质量评分、真机/CWV 或生产检查，未修改代码来自动 index/noindex。

## 9. 单页交付判据

- [ ] 已写独立意图、最近似页面和至少一项带位置/证据的独有贡献。
- [ ] controls、how-to、features、tips、mobile、fullscreen、加载/错误、source、images 逐项有事实状态；没有用“结构通过”顶替操作证据。
- [ ] FAQ 每问有实际依据和答案证据；可见、DOM、键盘和 schema 一致性分别核对。
- [ ] 未测行为、作者、日期、权限和统计保持未知；没有取消任务复活或未经批准的范围变化。
- [ ] AI/编辑自查与人类审核分列；缺少人类审核不写 CT-06 通过。
- [ ] 适用的规则与检查有日期、版本、完整命令/退出码、失败与未覆盖范围；原证据没有改写。
- [ ] 当前任务仅待验收；后续页面、发布和索引变动没有自动发生。

回滚限本项标准、模板及治理引用增量；不回退已验收应用、共享规则、Registry 或历史 QA。后续规则变更须标明版本与理由，不用更新标准来抹去已有失败。
