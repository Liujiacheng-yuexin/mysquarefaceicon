视觉相关的硬性约束（性能、可访问性）见 `RULES.md` 的 `PF` 与 `AY` 章节，本文件只描述风格。

## 设计原则

- 首屏必须直接展示核心功能或核心价值。
- 不做空洞 landing page。
- 工具站优先让用户直接使用工具。
- 内容页首段必须直接给答案。
- 页面结构要清晰，适合移动端。
- 不使用过度装饰。
- 不使用大面积无意义渐变。
- 不使用影响可读性的低对比度文字。
- 不把 UI 卡片套在其他卡片里。
- 不让文字溢出容器。
- 不让移动端横向滚动。

## 首屏要求

首页首屏应明确回答：

- 这是什么网站？
- 用户能在这里做什么？
- 核心功能入口在哪里？
- 为什么用户应该继续停留？

首屏应包含：

- H1。
- 简短价值描述。
- 核心操作入口。
- 1 个主 CTA。
- 必要时提供热门入口或示例。

## 组件规则

- 按钮：明确、可点击、文案短，必须有可访问名称（AY-01）。
- 不要把正文、标题、FAQ 或内链锚文本放进 CSS `content`（KW-06）。旧版曾建议用 CSS `content` 移出重复按钮文案以调节关键词密度，该做法已废除——原因见 `RULES.md` 附录 E。
- 输入框：必须有 label 或可访问名称。
- 卡片：用于重复项目、结果、列表项，不用于包裹整块页面区域。
- 表格：移动端必须可读。
- FAQ：可折叠或列表，但内容必须可索引。
- 导航：优先暴露核心页面和高价值入口。
- 页脚：必须包含 About、Contact、Privacy Policy、必要时包含 Disclaimer 和 Editorial Policy。

## 图片、动画和视频

允许使用图片、动画、AI 图片或视频，但必须满足：

- 服务理解、展示、工具结果、品牌记忆或分享。
- 不替代正文内容。
- 不拖慢核心页面。
- 有明确文件名、alt 和上下文。
- 风格统一。
- 不用于掩盖薄内容或重复内容。

动画应轻量，优先 CSS 或低成本交互，避免影响 LCP / INP / CLS（PF-08）。

图片必须设置 `width`、`height`（PF-03）——缺失是 CLS 失败的第二大来源，第一大是没有预留高度的广告位与嵌入（PF-04）。

## 页面确认要求

每个页面开发前必须输出格局布置方案，并等待用户确认。

格局方案必须说明：

- 从上到下的模块顺序。
- 每个模块的视觉样式。
- 哪些组件复用模板现有组件。
- 哪些区域需要新设计。
- 桌面端和移动端布局。
- 图片、动画、图标、交互位置。

## 禁止事项

- 不要让文字溢出容器。
- 不要让移动端横向滚动。
- 不要把核心功能藏在首屏以下。
- 不要做只有视觉、没有功能的页面。
- 不要堆砌无法解释的装饰元素。
- 不要用绝对化、恐吓式或虚假承诺文案。
