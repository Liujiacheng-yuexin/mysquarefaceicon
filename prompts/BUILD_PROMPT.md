# BUILD_PROMPT.md

复制下面代码块中的内容，作为模板改造项目的启动提示词。

**这是启动提示词，不是项目运行时的约束来源。** 真正的规则在 `RULES.md`。

---

```text
这是一个已经创建好的网站模板项目。请不要重写整个项目，也不要马上写代码。

目标：基于当前模板改造成一个高质量、可上线、可扩展的 SEO 网站。模板已有页面结构、
组件、样式和技术栈，请优先复用，只在必要时做内容、SEO、视觉和交互改造。

## 第一步：读取规范

先读 AGENTS.md，按它的「加载策略」决定还要读哪些文件。不要一次读完所有文档。

本次是项目启动，所以需要读：
  AGENTS.md、RULES.md、STRATEGY.md、PROJECT_BRIEF.md、
  PAGE_PLAN.md、SEO_PLAN.md

RULES.md 是唯一规范来源。后续所有交流请用规则 ID 引用（如 IDX-03、KW-04、LINK-02）。

同时检查：package.json、框架配置、路由文件、组件目录、样式文件、
以及我提供的关键词 Excel / 问题 Excel。

## 第二步：分析，不写代码

### A. 模板现状

1. 技术栈与框架版本
2. 现有页面清单
3. 可复用的组件
4. 样式系统与视觉风格
5. 现有 SEO 基础（metadata / sitemap / robots / canonical 各自怎么实现的）
6. 哪些页面保留 / 改造 / 删除 / noindex

### B. 关键词 Excel 分析

我通常会提供关键词 Excel（按热度排序）和问题 Excel（按热度排序）。

**不要把每一行都做成页面。** 必须先按搜索意图分组（IA-02）。

按以下类型分组，每组说明：代表关键词、搜索意图、建议 URL、页面类型、
是否 index、优先级 P0/P1/P2、合并或拆页的理由。

  - 首页主词
  - 核心工具 / 功能词
  - 聚合页词
  - 详情页 / 模板页词
  - 博客 / 指南词
  - FAQ 词
  - 暂不开发 / noindex / 合并词

判断能否单独建页，用 IA-02 的五条标准。只是词序不同、同义表达、
或换个地区数字标签但内容无实质差异的，一律合并。

### C. 问题 Excel 分析

按以下类型分组：适合独立 blog 的 / 适合放入核心页 FAQ 的 /
适合作为页面 H2-H3 的 / 适合做教程的 / 暂不处理或合并的。

每个建议 blog 说明：标题建议、主关键词、搜索意图、建议 URL、
内链到哪些核心页面、是否需要 FAQ schema、优先级。

### D. 输出

请输出以下几节：

  ## 模板现状总结
  ## 关键词分组
  ## 问题分组
  ## 推荐网站信息架构
  ## 首批页面开发顺序
  ## 首批 Blog / FAQ 计划
  ## 低质量页面风险提醒
  ## 创建输出表单任务草案
  ## 需要我确认的问题

「创建输出表单任务草案」按这些字段列出：
任务描述、URL、网站、状态、任务截止日期、预估工作量。
没有明确截止日期写「待定」，没有预估工作量留空。

如果本次任务涉及给已有页面补充关键词文案，额外输出映射表（KW-11）：
关键词组 / 对应现有 URL / 对应文件路径 / 建议插入位置 / 保留哪些原内容 /
新增文案目的 / 是否存在覆盖或重复风险 / 需要我确认的项。

在我确认整体方向之前，不要写代码。

## 第三步：逐页确认后才开发

每开发一个页面前，先输出「页面格局布置方案」并等我确认。格式见 PAGE_PLAN.md。

方案必须包含：

  页面名称 / URL / 页面目标
  SEO 设置：主关键词、次级关键词、对应 Excel 行、Title、Description、H1、
           Canonical、Index 建议、Schema
  关键词位置覆盖计划（KW-01）：Title / H1 / 首段 / H2 / 入链锚文本
  语义覆盖清单（KW-04）：SERP 前 10 共同覆盖的子话题，本页覆盖哪些、
                        缺哪些、为什么不写、预计覆盖率
  页面格局：从上到下每个模块的目的、内容、用户动作、SEO 作用、
           是否复用现有组件、是否需要图片动画交互
  视觉方向与移动端布局
  内容质量：本页有哪一项独有内容（CT-05）、预计能获得几条入链（LINK-02）、
           是否与其它页面重复、是否需要 noindex
  需要我确认的问题

在我明确回复「确认」之前，不要开发该页面。

## 开发时的约束

- 遵守 RULES.md 全部「必须」级规则
- 遵守现有技术栈，优先复用已有组件和样式
- 不擅自创建未确认的页面
- 给已有页面补充文案时只能增量补充（KW-10），不能整页覆盖或删除原内容
- 不生成低质量占位内容，不开放低质量页面 index
- 多语言页面必须独立调研主关键词（I18-07），不直接机器翻译
- 不破坏移动端体验，不为视觉牺牲 SEO 和性能

## 开发完成后

先跑自动检查：

    node scripts/seo-check.mjs --base http://localhost:3000

必须级失败必须清零才算完成。然后按 AGENTS.md 的「交付报告格式」输出，
包含：修改的文件、完成的页面、seo-check 结果、按规则 ID 的符合性说明、
移动端与视觉检查、性能实测数值、待确认项、lint/build 结果、
以及是否已更新 SEO_LOG.md 和创建输出表单.md。

注意：不要报告「关键词密度已达 3%-5%」——该指标已废除，
原因见 RULES.md 附录 E。要报告的是位置覆盖（KW-01）和语义覆盖率（KW-04）。

每完成一个页面后停下来，问我是否进入下一个页面规划。
```

## 使用提示

- 首次使用前，先填写 `PROJECT_BRIEF.md`，尤其是 **AI 爬虫策略**（AI-01）那一节——它是必填的项目级决策。
- 关键词 Excel 和问题 Excel 放在项目根目录。
- 如果项目还没有 `scripts/seo-check.mjs`，从知识库的 `网站开发/scripts/` 复制过去，并创建 `seo-check.config.json`。
